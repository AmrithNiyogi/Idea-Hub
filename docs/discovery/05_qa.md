## 3. Edge cases and negative tests

- **Empty states:** fresh install with no ideas; ideathon module with none; user with zero votes; filter with zero results; reviewer with an empty queue.
- **Anonymity:** author identity must not appear in rendered text, tooltips, activity, similar-idea suggestions, co-author lists, or after a merge into a named idea. Test that a co-author added to an anonymous idea does not reveal the submitter. Note that localStorage is readable on the device, so anonymity is a UI guarantee only, not a security control. This must be stated to the founder.
- **Merged ideas:** merge into a declined or archived target; circular merge (A into B, then B into A); votes and comments carried over; ideathon link on the merged idea.
- **Duplicate votes:** rapid double-click; the same user in two tabs (use the storage event to resync); vote, then merge.
- **Drafts:** draft referencing a category that an admin later disables; draft after reset demo data.
- **Deleting or declining ideas linked to ideathons:** the shortlist and submission counts update; a winner cannot be deleted without a recorded reason; closing an ideathon does not orphan linked ideas in review.
- **Storage:** missing key; unparseable JSON; valid JSON with missing fields; quota exceeded (typically around 5 MB per origin, varies by browser, to verify); storage disabled or private mode, where the app should run in memory with a warning.
- **Schema version:** older data upgrades through a migration; an unknown or newer version is rejected safely without wiping data.
- **Reset:** reset in one tab while another is open; reset while viewing a detail page for a deleted idea.
- **Long and hostile text:** 5,000-character problem statement; a 300-character unbroken title; emoji; right-to-left text; `<img onerror=...>` in titles and comments, which must render as escaped text.
- **Date boundaries:** SLA due exactly at now; ideathon end at 23:59 versus 00:00; quarter boundary at 2026-12-31 and 2027-01-01 for Idea of the Quarter; system clock moved backwards.

## 4. Test approach

**Automated (Playwright, file://, Chromium first):**
- Load the single HTML file through file://. Fail on `pageerror`, on `console` errors, and on any unexpected network request. Playwright is reported as available in our environment; I have not verified the installed version or its clock API.
- Use a fresh browser context per test so localStorage starts clean.
- Journey scripts per persona (submit, review, deliver, recognise). Assert against the stored state via `page.evaluate`.
- Dead-control scan: enumerate buttons, links, `[role=button]`, inputs and selects. Activate each in a disposable context. Pass if the DOM, URL hash, dialog or storage changed. Report any control that does nothing. Disabled controls must show a reason.
- Date tests: inject a fixed clock (verify Playwright clock support before relying on it).
- Viewports: 375x812, 768x1024, 1280x800, 1920x1080. Check no horizontal overflow and that primary actions remain reachable.
- Optional: axe-core in the test harness only. It must not ship in the HTML.

**Manual review:**
- Dotkonnekt fidelity, compared visually against the Dotkonnekt artifact. Exact tokens are unverified, so numeric matching is not possible.
- Copy and tone; clarity of AI labelling; a walkthrough by someone who did not build the app, against the persona journeys.
- Keyboard and screen-reader spot checks.
- Firefox and Safari smoke tests. Automated runs cover Chromium only unless other engines are installed.

## 5. Quality gates

Severity: P0 is a crash, blank screen or data loss. P1 is a broken core journey or dead control. P2 is an incorrect secondary display. P3 is cosmetic.

- **Gate 0, architecture sign-off (Phase 3):** entity model with IDs; idea status state machine; schema version; anonymity rules; rule set for points. Each has a test oracle.
- **Gate 1, shell and data layer:** file loads from file://; zero console errors; seed loads; persistence round-trip; reset; corrupted-storage fallback (C1, C4, C5, C8).
- **Gate 2, per module:** that module's checklist items pass; dead-control scan clean for the module; smoke journey from earlier modules still passes.
- **Gate 3, integration (Phase 7):** every consistency matrix row verified; cross-module journeys pass; recognition worked examples reproduced.
- **Gate 4, QA sign-off (Phase 8):** full checklist re-run with results and evidence recorded; four viewports; no open P0 or P1; known limitations logged in the decision log.

No phase closes with open P0 or P1 items.

## 6. Top risks

1. **Regressions in a growing single file.** Mitigation: one state store, one derived-selector layer, and the smoke suite run at every gate.
2. **State drift between views** (dashboard versus list). Mitigation: all counts derived from one source; consistency matrix tests.
3. **file:// constraints.** ES module imports and fetch of local JSON are blocked in Chromium, and localStorage may be shared across file pages. Mitigation: inline everything; isolate test contexts.
4. **Simulated AI mistaken for real AI.** Mitigation: one shared "Simulated" component used everywhere; copy review.
5. **Anonymity leaks through derived views** (counts, profiles, similar-idea hints, activity). Mitigation: a leak scan that searches rendered text for seeded author names on anonymous ideas.
6. **Storage quota and migrations** as attachments grow. Mitigation: store attachment metadata only and cap sizes; migration tests.
7. **Flaky date tests.** Mitigation: injected clock.
8. **Scope creep against a 70-item checklist.** Mitigation: P0 and P1 journeys first.
9. **Unverified design tokens** risk a false claim of brand fidelity. Mitigation: label all values "provisional approximation pending tokens.css".
10. **Recognition gaming through volume or votes.** Mitigation: G2 and G3 as explicit tests of the rule set.
